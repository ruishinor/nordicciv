# D05 — Land-cover pilot preparation

Prepared from NordicCiv's D02 terrain index on main `a0f144548b9f99d2618ef319954edd4d2d26eea6`. This is a separate acquisition and GIS-processing utility, not a renderer change or a finalized runtime data contract. D03R stays with Codex.

## Start here

Use ESA WorldCover 2021 v200 as the shared land-cover layer. Its classification covers all three pilots and can later cover Scandinavia. Add the 2021 Copernicus Tree Cover Density (TCD), Dominant Leaf Type (DLT) and Grassland layers when the relevant raster files are available. Preserve each thematic layer independently: TCD is canopy coverage, DLT is dominant leaf type, and grassland does not establish grazing. WorldCover herbaceous wetland does not cover every kind of wetland. The optional Copernicus wetness and crop-type products have separate meanings and are not silently merged into those classes.

Herning can additionally use the annual Danish Marker field polygons. The source describes declared agricultural fields, not land ownership or surveyed cadastral boundaries. CC0 is reported by two secondary sources, but the official layer-specific licence record could not be read here; keep field outputs private until that statement is checked. The utility requests geometry only and strips all attributes on export. Norwegian FKB-AR5 is restricted according to NIBIO's download policy. Do not fetch it without the required rights. AR50 is a more general Norwegian land-resource alternative, not a substitute for actual field geometry. No reusable Norwegian field-boundary source was confirmed in this preparation.

See `sources.json` for product IDs, access routes, class definitions, years, coordinate systems, licence links and attribution. The 2021 baseline is a pinned choice, not a claim of current conditions. Marker 2024 and Water and Wetness 2018 have different reference years. Do not harmonize them silently.

## Run from the repository

Use the existing Python environment and `requirements-terrain.txt` first. Required libraries: numpy, pyproj, rasterio; shapely 2 is needed only for fields. Python 3.11+ for file hashing. Install only a missing declared dependency into the existing virtual environment. All output defaults to `data/raw/d05-prep/`, outside the web application.

```powershell
Set-Location 'C:\00 DEV\In Progress\NordicCiv-Repository'
$py = '.\.venv\Scripts\python.exe'
& $py -c 'import numpy, pyproj, rasterio, shapely; print("D05 dependencies available")'
& $py tools/d05_landcover.py plan --region oslo-lillestrom
& $py tools/d05_landcover.py plan --region aurland
& $py tools/d05_landcover.py plan --region herning
```

Compare the pinned pilot bounds and projection in `sources.json` with the current `web/terrain/index.json` before acquiring if the D02 pilot changes. Do not expand the bounds during D03R.

Acquire WorldCover once per pilot, using range windows rather than full three-degree objects. The tool first verifies HTTP 206 and a bounded byte range; GDAL is then restricted to cropped source windows, with no retry loop. The source crop is cached and its SHA-256 checked on reuse. The program bounds pixels, not exact network byte consumption by GDAL. If a server refuses the probe or a crop fails, stop; do not fall back to full-country or full-tile downloads. Network access is necessary only on the first acquisition.

```powershell
& $py tools/d05_landcover.py worldcover --region oslo-lillestrom
& $py tools/d05_landcover.py worldcover --region aurland
& $py tools/d05_landcover.py worldcover --region herning
# Rebuild from cached crops, without another download:
& $py tools/d05_landcover.py worldcover --region herning --offline
# Optional: point to existing original WorldCover COGs instead of the network:
& $py tools/d05_landcover.py worldcover --region herning --local-dir 'C:\path\to\existing-worldcover-cogs'
```

The exact candidate WorldCover object names are generated by `plan`: Oslo–Lillestrøm N57E009 and N60E009; Aurland N60E006; Herning N54E006 and N54E009. The URLs are derived from the documented AWS naming convention. This execution environment could not resolve the external data host, so the object responses and range behavior have not been verified live.

For the CLMS layers, use the official product page/Download by area and time or the CDSE dataset identifier and catalogue access route from the manifest. Choose only the geographic bounds printed by `plan` and the specified reference year. Authentication may be needed. Do not purchase API usage or put credentials in Git. Download native single-band classification TIFFs, not styled WMS images. Retain the source metadata and licence with the input. Example (replace the path with the actual bounded file; multiple input TIFF paths are supported):

```powershell
& $py tools/d05_landcover.py raster --region herning --source clms-tcd --year 2021 --input 'C:\path\to\TCD_2021.tif'
& $py tools/d05_landcover.py raster --region herning --source clms-dlt --year 2021 --input 'C:\path\to\DLT_2021.tif'
& $py tools/d05_landcover.py raster --region herning --source clms-grassland --year 2021 --input 'C:\path\to\GRA_2021.tif'
```

The year argument records the reference year selected by the operator; the tool does not authenticate a filename or verify that its contents belong to that year. For Denmark, `plan --region herning` prints the WFS schema and hits URLs. Inspect the live schema to identify the exact geometry field before issuing the bounded request. The server must report a finite hit count and return the same number of geometries, identify EPSG:25832, and honor geometry-only projection. Limits: 20,000 features and 32 MiB response. No automatic fallback to the national ZIP. Use a local bounded GeoJSON if the WFS is unavailable:

```powershell
# Read the schema, then replace GEOMETRY_PROPERTY with the actual field name.
& $py tools/d05_landcover.py fields --region herning --geometry-field 'GEOMETRY_PROPERTY'
# Or use a local bounded file with its correct CRS:
& $py tools/d05_landcover.py fields --region herning --input 'C:\path\to\herning-marker-2024.geojson' --input-crs EPSG:4326
```

## Outputs and size

Each raster is a separate single-band, DEFLATE-compressed GeoTIFF in Nordic LAEA metres (same projection as the application, with metres rather than kilometres). Output cells use nearest native pixel-centre sampling. GeoTIFF bounds are exactly the pilot rectangle. Sidecar JSON records the input hashes or crop metadata, projection, grid spacing, counts, unknown codes, byte size and SHA-256. Valid zero remains zero, unknown/unavailable is 255. Source classes are not silently combined. A file with incompatible nodata or conflicting valid overlapping source values fails explicitly. Vector output uses standard WGS84 GeoJSON; polygons are clipped in the Nordic projected frame before transforming back. The preparatory format is not a new browser contract.

| Pilot | Area km² | 10 m shape (rows × cols) | Raw bytes / uint8 band |
|---|---:|---:|---:|
| Oslo–Lillestrøm | 707.7888 | 2304 × 3072 | 7,077,888 |
| Aurland | 235.9296 | 1536 × 1536 | 2,359,296 |
| Herning | 235.9296 | 1536 × 1536 | 2,359,296 |
| Total | 1,179.648 | 80 tiles at 3.84 km | 11,796,480 |

At 30 m the same bounds hold 1,310,720 samples per band. Four 10 m uint8 bands would use 47,185,920 bytes (~45 MiB) uncompressed, excluding indexes, provenance, vectors and source caches. Real compressed sizes depend on the data and must be measured after acquisition. Do not use compression of synthetic fixtures as an estimate. A 3.84 km tile is 384 × 384 cells at 10 m (144 KiB per band before compression) and 128 × 128 at 30 m. Do not load all pilots at once in the browser.

## Targeted preparation checks

Local Python processing checked all three planned grid sizes and five source-object URLs. Synthetic (not geographical) inputs were used to exercise the actual implementation in Rasterio 1.5.0 and Shapely 2.1.2: two adjacent source windows covering a Herning-sized grid (2,359,296 cells) produced complete classification, zero overlaps and gaps; cached window hashes matched on offline reuse; a 30 m canopy raster retained both valid zero and nodata; a clipped field polygon preserved its interior hole, discarded an outside polygon and removed its attributes. This uncovered and corrected an overlap caused by independent approximate tile reprojection. No nationwide dataset or actual geographic source bytes were acquired. The remote acquisition and WFS response paths remain unverified live. No production assets are supplied, and no application test workflow was initiated by the preparation process.

## Codex handoff

After D03R and D04 are integrated, reuse the manifest and utility to acquire a bounded pilot, beginning with Herning and one contrasting Norwegian site. Inspect generated raster class counts, actual coverage, sources and source dates. Use the current shared surface contract; do not treat this preparatory interchange format as a competing renderer interface. Retain detailed water exclusions from D04. Use measured canopy coverage to constrain deterministic illustrative trees; never claim individual tree positions or infer building footprints. Use actual field polygons only if rights and usable geometry are established; otherwise render mapped cropland as an illustrative surface. Use no additional high-resolution dataset unless a concrete visual or geographic deficiency requires it. Keep source data and caches outside Git; commit only validated derived runtime assets after D05 integration, with source attribution and provenance.
