# Project writing standard

Apply this to all copy in this project: UI, labels, tooltips, legends, charts, advisors, onboarding, error messages, generated descriptions, README, guides and documentation.

- Common conversational language only. Use plain English (or natural Norwegian Bokmål where appropriate). Say what the feature does or what the figure means.
- Avoid moralising, defensive, clinical, academic, consultant and AI-style language. Do not use phrases such as "reading honestly", "nothing is invented", "evidence-based", "evidence-led", "absence is not evidence of absence", or "trustworthy" to describe the product. Never suggest that other parts of the product could be made up.
- Name actual sources, figures, dates, measurements and test results instead of speaking about evidence or credibility.
- Explain what is included directly. Keep necessary qualifications about estimates, missing data, coverage and safety short and specific. Do not present estimates as published statistics or remove material source information.
- Use technical terms only where needed, and explain them in plain language. Preserve code identifiers, licence notices, quotations and historical records.
- Review the interface, generated descriptions and documentation before every release. Fix copy at its source and in shipped outputs. Do not make unrelated changes or use blind global replacements.

Examples:
- "Reading the map honestly" → "Map data and definitions"
- "Nothing is invented" → name the published sources.
- "Absence is not evidence of absence" → "The map includes plants above the listed minimum capacities."
- "Evidence-based observations" → state the actual finding.
- "Not integrated (missing coverage, not zero)" → "Data unavailable for this country."
- "Evidence ledger" → "Requirements and test results."
